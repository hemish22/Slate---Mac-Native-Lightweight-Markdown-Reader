# Publishing this prepared repository

Run these commands from a normal macOS desktop with GitHub access. The publishing helper uploads the code and captures real app screenshots before publishing.

## One-command publication

Install the GitHub CLI if necessary, authenticate, then publish:

```sh
# If you already use Homebrew:
brew install gh node

gh auth login --scopes repo,workflow
cd /path/to/markdown_reader
bash Scripts/publish.sh
```

The publishing script validates the project, captures all three app views using the demo document, and updates the README image section. It clones the target repository into a temporary directory under `build/`, copies only the project files, commits the changes on the repository's default branch, and pushes without force. Existing remote history is retained. It does not post to social media or create a release tag.

For development after publishing, use a normal clone of the GitHub repository. The original preparation folder may not contain `.git` metadata.

If you only need to publish code and the launch graphic, and cannot run a desktop capture, use:

```sh
SLATE_SKIP_SCREENSHOTS=1 bash Scripts/publish.sh
```

In that case the README retains its screenshot capture instructions rather than claiming full-window screenshots have been added.

## Create a downloadable release

The first push uploads the code, not a binary release. In a normal authenticated checkout, push a matching version tag to run the release workflow:

```sh
git tag v1.0.2
git push origin v1.0.2
```

The workflow builds a universal app and publishes `Slate.zip` and `SHA256SUMS`. Archives are ad hoc signed and are not notarized. An Apple Developer ID and a separate signing/notarization setup are required for notarized distribution.
